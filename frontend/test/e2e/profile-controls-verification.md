# Phase 6 — profile/account story verification

## Scope and decisions

- Uses the referenced revision-3 dashboard as visual-language guidance only; no admin artboard exists. Keeps the existing profile cards, routes, fields, all theme choices and semantic shared panels. No forced theme, migration, animation or backend changes.
- Preference storage/synchronization (`use-preferences.ts`) is unchanged. Quick actions remain in the existing inventory table-settings control, not a new profile field.
- `LanguageSelector` now associates labels with the actual select triggers and wraps long values. `Form/Password` uses a named, pressed-state reveal button with visible keyboard focus and reserved input space.
- Duplication settings no longer duplicate the switch/input ID. Prefix saving now consumes the emitted input value (the former native input handler read the previous value).
- API-key expiry and one-time token fields have accessible names. Escape/overlay/close dismissal clears the one-time token; no screenshots are taken while a token is shown. Test tokens/passwords are synthetic, never production credentials.
- Account deletion returns after success instead of also emitting the failure toast. Password/key errors are inline alerts retaining entered values; loading-key errors are not presented as empty lists.
- Existing collection action visibility is membership-count dependent (sole member: delete, shared member: leave), not a new owner/member permission model. Tests exercise these real branches and unchanged tabs; mocked responses do not establish backend authorization correctness.
