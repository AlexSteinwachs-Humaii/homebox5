# CSV record-list coverage contract

Audited against `frontend/pages` and `frontend/components` (including every `v-for`, selector, tree and shared Item/View consumer). This is the **foundation inventory**, not a claim that buttons/adapters already exist. “UI integration” identifies the insertion point and the implementation story (S4–S8); S4 inventory integrations are implemented; S5–S8 remain pending. S2 implements source adapters, S3 authorization/lifecycle. No reporting dashboard is introduced.

`backend/internal/core/services/csvexports/registry.json` is the authoritative source/column/filter/access allowlist. `source-registry.generated.ts` and `../api/types/csv-contracts.generated.ts` are generated with `cd backend && go run ./app/tools/csvcontractgen` (also run by `task typescript-types`). `source-registry.ts` narrows UI descriptors to the source's scope, columns and boundary kinds. Changes require updating this matrix, regeneration and contract tests.

## Rules common to every row

- Full queries are not loaded-page exports. No page/pageSize/offset exists in the contract. Recent lists have an intentional `recent.limit`; explicit sets contain the **complete** matched ID set in display order, not the virtualization slice. Empty explicit sets are empty, never “all”. History captures IDs before adding its own CSV job.
- Columns are ordered `{id,label}` data columns from the allowlist. Tables use actual visible order; cards/trees/auxiliary records use the displayed field set. No checkbox/action/image bytes/blob path/authenticated URL/hidden credential column is eligible. Invitation exports contain metadata only, never one-time tokens. Full values, not visual truncation. `parentId/path` provide tree context independent of expansion.
- Collection source IDs come from trusted auth/tenant context, not request-supplied identity. Entity/template IDs are source constraints only and must be authorized. Private sources never acquire a group scope. Client-provided IDs/snapshots never confer permission.
- `member` means current tenant member. `requester-member` additionally means the requesting user's source rows only. `source-access` means each historical artifact's original source policy must still hold. `requester` is authenticated user only, independent of collections. `requester-membership` revalidates every included collection. `referenced-entity-access` revalidates every referenced record before copying displayed values into a privately retained CSV. `collection-owner` revalidates ownership of the visible invitation's collection.
- `snapshot` is bounded, schema-constrained displayed draft/external data. It is not a general object map or a database read instruction. Resolvers must verify visible invitations and referenced entities; draft photos only contain name/MIME/size, never file content.
- Retention policies default to 30 positive whole days. Collection policy updates require owner authorization; private updates use the authenticated user and work without a tenant. Policies are captured per request; expiry is fixed at completion + captured days. The arithmetic cap of 106751 days is a Go duration limit, not a business retention limit.

## Explicit exclusions (not unexplained omissions)

- `App/QuickMenuModal`, page tab loops, sidebar/header/navigation, theme/language/currency/icon/color choices, date/calendar controls, camera-device choices: static configuration or navigation, not product record lists.
- Home/maintenance statistics: aggregate scalar metrics, not rows of records. No new report source.
- Table column settings, pagination items, sort/status/attachment-type options, bulk-edit toggles: view controls, not source records. Print propertyInputs/layout knobs/blank placeholders are excluded.
- `DetailsSection` main/purchase/warranty/sale properties and edit mainFields/purchaseFields/warrantyFields/soldFields: fixed properties of **one** entity, not repeated records. Custom fields are explicitly included above.
- `pages/a/[id].vue` and `pages/label/[id].vue` are compatibility redirects; `components/global/LabelMaker.vue` and QR/barcode renderers show a single label image, not a repeated record list. Report label record output is covered above. ImageDialog has no separate record query, and its gallery descriptor is covered above.
- Display-only Tag/Chip, Item/Card, Location/Card, Template/Card and tree Nodes belong to the containing list. No action inside each selectable row, no duplicate export per child. Associated tag/breadcrumb/AR-child records have explicit rows above.

## Lifecycle handoff

Dedicated `csv_exports` rows record requester, optional collection (NULL for private), source policy, immutable request snapshot/retention, status and server-only artifact path, completion and fixed expiry. No CSV row appears in `exports` or portable ZIP archives. Foreign keys restrict deleting a requester/collection while a CSV blob pointer remains; S3 must remove blobs before rows before user/group deletion. No public CSV route or generation worker is registered in this foundation story; therefore no artifact can be created through the existing API before authorization/lifecycle is implemented. Swagger's existing live-route contracts are intentionally unchanged. The separate generated CSV API contracts are ready for S3's endpoint integration.

## S2 source-resolution handoff

`CsvExportRepository.ResolveSource(ctx, authenticatedUID, trustedGroupID, request)` reads in a serializable transaction, checks membership/owner/requester constraints, reuses unpaginated list repositories and projects allowlisted fields. `csvexports.Resolve` preserves complete explicit client-match order, exclusions, captured multi-sort and intentional recent limits; `csvexports.Write` emits ordered headers/typed cells with spreadsheet-formula protection. Source adapters cover all registry entries. Invitation-visible exports are **metadata only** (token columns/snapshots rejected) to satisfy the no-credentials criterion. No UI or lifecycle endpoint is added in S2.

Client fuzzy searches must capture the complete matching ID set as `explicit`; `search` on other non-entity lists is a case-insensitive name substring. Entity filters reuse `EntityQuery` (including description/identification/notes search and descendant tags). Recent membership is the existing createdAt-descending set, sorted for presentation only after limiting. Eligible custom-field option sets are deduplicated collection-wide; fieldName switches from field-name to value matching. Attachment size is absent in the existing metadata model and exports empty if requested; no blob reads/URLs are introduced. Histories project metadata before the new export is stored; ZIP errors are generic to prevent storage/credential details leaking from diagnostic strings. Lifecycle callers still must revalidate source access at download (S3).

Asset-route exports use `asset-results`, not the item-only EntityQuery source: QueryByAssetID includes both item/location and archived matches. The caller must supply assetId.

## S3 lifecycle handoff

`AllServices.CSVExports` now provides generation, current-source-authorized status/history/download/delete and failed-job retry. Authenticated `/api/v1/group/csv-exports` and account-only `/api/v1/user/csv-exports` support POST/GET, `/{id}`, `/{id}/download`, `/{id}/retry`, DELETE `/{id}`, GET/PUT `/retention`. Private routes do not run tenant middleware; the API integration test exercises an account with zero memberships and no default collection while sending an unrelated X-Tenant. Generated `CsvRequest`/`CsvArtifact`/`CsvRetentionSettings` contracts remain unchanged. Full endpoint/recovery details: `backend/internal/core/services/csvexports/LIFECYCLE.md`.

The database is the durable CSV queue. A separate five-second worker recovers abandoned running claims; generation has a five-minute deadline and a ten-minute abandoned-claim threshold. Failed jobs retain metadata/pointers and require explicit requester retry. Successful artifacts cannot regenerate; initial saves and later re-downloads use only the authorized canonical download. Storage keys are persisted before writes, exact-match validated and never exposed. Cleanup reloads the latest pointer after marking deleting, removes the blob before metadata, retries errors and treats missing blobs idempotently. User/group service deletion cleans CSV first with restrictive FKs as a concurrency safeguard. Completion-based captured-policy expiry is enforced before bytes independently of cleanup. ZIP tables/import/purge behavior is unchanged.

Invitation-visible private snapshots now recover their originating collection through each stored invitation ID, rechecking current ownership, instead of requiring a transient tenant that private artifact metadata intentionally does not retain. Requester-member notifier exports cannot be read from another member's history. Both CSV route bases send no-store headers and bypass PWA API caching.
